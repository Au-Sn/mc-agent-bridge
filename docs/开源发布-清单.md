# 开源发布清单（上传 GitHub 前逐条打勾）

> 用途：把**内部开发仓**变成一个可以公开的仓库。本文只讲"发布"这件事，不重复功能/安装说明
> （那些在 `README.md` / `INSTALL.md`）。
> 原则：**公开仓用干净快照，不推本机历史**；第三方资产不随仓库分发；密钥当作已泄露处理。

---

## 一、三条硬事实（先记住）

1. **不要直接 push 本机旧历史**。开发仓 `.git` 约 **441 MB**，历史里含
   `mod/jdk17.zip`（≈178 MB）、`mod/gradle-8.1.1-bin.zip`（≈119 MB）、`mod/gdist/` 发行版，
   以及**初始提交里曾经有过的密钥**。GitHub 每文件 100 MB 上限，且历史清洗后 670+ 提交 hash 全变、
   台账里的 hash 引用会对不上。
   **推荐**：用干净快照 → 新仓库 → push（见 §二）。
2. **密钥按"已泄露"处理**：历史里出现过 `secrets/deepseek.key`（后来已撤销/轮换，但历史 blob 仍在）。
   无论走哪条路，都去 **DeepSeek 控制台重新生成/轮换 key**；公开仓不允许出现 `secrets/`。
3. **公开仓必须有的文件**（干净副本判据会检查）：
   `README.md`、`INSTALL.md`、`LICENSE`、`CONTRIBUTING.md`、`dsh.env.example`、
   `tools/paths.py`、`tools/doctor.py`、`tools/recover.py`、`tools/check_all.py`、
   `tools/portability_test.py`、`mod/build.gradle`、`mod/src`、`state/exceptions.json`。
   **不应包含**：`dsh.env`（只留 example）、`secrets/`、`logs/`、`downloads/`、`backups/`、
   `jobs/`、`memory/`、游戏实例、第三方 mod jar、构建工具链（JDK/Gradle）。

## 二、推荐发布路径：干净快照 + 新仓库

```powershell
# 0) 先确认工作区干净、离线闸门全绿（发布前最后一道）
git status --porcelain
py tools\check_all.py --offline
py tools\release.py --check

# 1) 预检（只读）：必需文件/体积/泄漏面检查（不导出）
py tools\export_public.py --check
#    → 机器行形如 `EXPORTPUBLIC ok=1 files=... bytes=... problems=0`

# 2) 导出干净快照（导出 HEAD 的跟踪树，自动排除工具链/日志/下载/备份/dsh.env）
py tools\export_public.py --out tmp\public --init-git
#    → 在导出目录初始化单提交 git 仓（branch=main）；--zip-only 只出 zip。具体以 `--help` 为准

# 3) 在导出目录里再验一次"缺什么"（cold_start 判据/脚本）
cd tmp\public\mc-agent-bridge
py tools\portability_test.py
py tools\doctor.py            # 游戏没开时退出码 2 是正常的
py tools\check_all.py --offline

# 4) 建远端并 push 这个干净仓（不要 push 开发仓）
git remote add origin <你的 GitHub 仓库地址>
git push -u origin main
```

> 如果 `export_public.py` 尚不可用：备选是 `git archive HEAD | tar -x -C <空目录>` 导出跟踪树，
> 再手工检查/删除不应分发的目录（`.gitignore` 之外的运行痕迹可能被跟踪）。
> **不推荐** `git filter-repo` 清洗旧历史再 push（会改写全部 commit hash、与台账引用失配、风险高）。

## 三、上传前逐条检查（复制成清单打勾）

### 3.1 仓库体积与内容

```powershell
# 跟踪文件数与各目录体积（应只看到小体积源码/文档/数据目录；没有 >50MB 的单文件）
$by = @{}
git ls-files | ForEach-Object {
  $p = $_
  if (Test-Path $p -PathType Leaf) {
    $top = ($p -split '/')[0]
    if (-not $by[$top]) { $by[$top] = [pscustomobject]@{ Files = 0; Bytes = 0 } }
    $by[$top].Files++
    $by[$top].Bytes += (Get-Item $p).Length
  }
}
$by.GetEnumerator() | Sort-Object { -$_.Value.Bytes } |
  ForEach-Object { "{0,-16} {1,8:N2} MB {2,5} files" -f $_.Key, ($_.Value.Bytes/1MB), $_.Value.Files }

# 大文件（应只看到少量数据文件；>50MB 一律不进仓）
git ls-files | ForEach-Object { if (Test-Path $_ -PathType Leaf) { $f=Get-Item $_; if ($f.Length -gt 50MB) { "{0:N1} MB  {1}" -f ($f.Length/1MB), $_ } } }
```

## 四、GitHub 仓库设置建议

- **License**：仓库里已有 `LICENSE`（MIT），GitHub 会自动识别为 MIT。
- **README/描述**：仓库描述写一句话（"让外部 Agent 在 Minecraft 里像玩家一样在场"），
  topics 建议：`minecraft` `forge` `carpet` `agent` `llm` `mcp` `automation`。
- **分支保护**：`main` 设为默认分支；要求 PR 才能合并（个人项目可只保护 force-push）。
- **Issues/PR**：开启 Issues 与 Discussions（可选）；PR 模板可引用 `CONTRIBUTING.md`。
- **Actions**：没有 CI 也能发布；如果要加，Windows runner 可跑
  `py tools\check_all.py --offline`（无游戏、无网络依赖），但 `live` 类判据不要放进 CI。
- **不要开 LFS**：第三方资产/工具链不该进仓库，不要用 LFS 把它们塞回来。
- **Release**：每次发版打 tag（如 `v2.57.0`），**jar 作为 Release 附件**分发，不要提交进仓库。
  Release 说明模板：版本号 / 变更摘要 / 判据与 live 实测结果 / sha256 / 已知限制。
- **安全**：开启 secret scanning / Dependabot alerts（项目无三方 Python 依赖，主要盯模组依赖）。
  私密漏洞请走 GitHub Security Advisories，不要在公开 issue 里贴 token/存档。

## 五、第三方资产与数据许可

- **不随仓库分发**：Minecraft、Forge、Carpet、CC:Tweaked、ATM9 整合包及其它 mod 的 jar/资源。
  README/INSTALL 里给的是**官方获取方式**；用户自行下载并遵守各自许可证。
- **随仓库分发的数据**（如 `build/recipes.json`、`state/tags_category.json`、`state/exceptions.json`、
  `state/export_snapshots/`）是**为兼容性生成的派生数据**：它们从整合包/游戏导出而来，
  再分发前请确认整合包与其 mod 的许可政策；若不确定，可在 release 里改为"首次运行自行生成"
  （`py tools/bootstrap.py export`）而不入库。
- **图片/皮肤/人设语料**（`skins/`、`personas/`、`docs/大肥鱼语料-来源与原文.md` 等）：
  确认来源与再分发权限；第三方素材请注明出处或替换为自产素材。
- 本仓库 `LICENSE` 已注明：代码/文档默认 MIT；第三方资料以各自许可证为准。

> **干净快照首跑已验证（2026-11-03）**：模拟 git-archive/zip（无 git）与单提交 clone 两种快照，
> `py tools/doc_consistency_test.py` 均 **37/37 PASS**、`py tools/generated_freshness_test.py` PASS。
> 相关闸门已改为"**git 提交时间优先、mtime 兜底**"（无 git 快照时显式跳过新鲜度项 ✗ 不冒充通过），

## 六、发布后 smoke（拿到 Release 的人按此验证）

1. 下载 `Source code (zip)` → 解压 → 按 `INSTALL.md` 配置 `dsh.env`。
2. 下载 Release 附件 `dshbridge-<ver>.jar` → 放进实例 `mods\` → 重启游戏。
3. `py tools\direct.py --health` ⇒ `ok dshbridge-http`；`py tools\doctor.py` ⇒ 硬问题 0。
4. `py tools\recover.py` ⇒ 假人被拉起并切生存。
5. `py tools\check_all.py --offline` ⇒ fail=0。
6. 打开 issue 反馈时附 `doctor.py --json` 输出（不要贴 token）。

## 七、维护循环（发布之后）

- 改代码 → 判据先行 → 离线闸门两遍同数 → `doc_consistency_test` → `release.py --check`。
- 升模组版本：`mod/gradle.properties` 单一真源 → 构建 → `install_mod.py` 验特征 → 重启 live 验收
  → `release.py --record` → 打 tag → 上传 jar 到 Release。
- 每轮发布在 `docs/项目总览.md` 现状卡片更新数字（受文档闸门管）；本清单只在**流程/边界**变化时更新。

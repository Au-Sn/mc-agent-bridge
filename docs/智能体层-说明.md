# 智能体层（agent/）—— 说明书

> 一句话：这是假人的**大脑 + 手脚**。
> 参考了 [mindcraft](https://github.com/siv237/mindcraft) 的「技能库 + 模型每回合挑一个技能」
> 与 [qWaitCrypto/MineBot](https://github.com/qWaitCrypto/MineBot) 的「Python 大脑 + Carpet 假人身」
> 两种形态；差别在于**身体是服务端权威的 Carpet 假人**，手脚是 **ComputerCraft 计算机 + 外设**。

---

## 1. 分层（谁负责什么，为什么不合并）

```
        ┌─────────────────────────────────────────────┐
        │  brain.py   决策：模型每回合只挑一个技能      │
        ├─────────────────────────────────────────────┤
        │  reflex.py  反射：还击/吃饭/防卡死（不走 API）│
        ├─────────────────────────────────────────────┤
        │  skills.py  技能：会验收、带治理、记账        │
        ├─────────────────────────────────────────────┤
        │  world.py   感知：只放可从权威来源核实的事实  │
        ├─────────────────────────────────────────────┤
        │  memory.py  记忆：目标栈/事实本/行动流水      │
        ├─────────────────────────────────────────────┤
        │  channel.py 通道：唯一与游戏通信的地方        │
        └─────────────────────────────────────────────┘
```

**为什么不合并成一个大文件**：这四层的失败方式完全不同 ✓
- 通道失败 = 通信问题（超时/队列/网关）
- 感知失败 = 解析问题（本地化、CJK、数据结构变动）
- 技能失败 = 动作问题（工具不对、落点偏了、没验收）
- 大脑失败 = 判断问题（选错技能、原地打转）
混在一起时，一个超时看起来和一次误判一模一样 ✗ —— 分开之后，日志能直接告诉你**是哪一层错了** ✓。

## 2. 文件一览

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `channel.py` | 下发指令、认领回传 | 首选 `POST /api/command`（网关会回传它**自己分配的 id**）；网关不在时退化为写 `bridge/inbox`，此时按「cmd+args+时间」**指纹认领** id。日志读取含轮转 ✓ |
| `world.py` | 生命/饥饿/背包/周边方块/实体/聊天 | **不靠英文短语解析**（服务端是中文、CC 渲染不了 CJK 会变 `?????`）→ 只按数值形状认；存在性用 `commands.exec` 的 `success` |
| `skills.py` | `scan/verify/goto/dig/place/sneak_place/chop/sift/equip/attack/flee/eat/craft/say/remember/done` | 每个技能**自带验收**；挖掘**按方块材质选工具**；脚手架技能（`give_item`）**默认禁用** |
| `reflex.py` | 常开保命：还击 / 吃饭 / 卡死检测 | 威胁响应**不经过模型**（等 API 回来人就死了）；事件队列喂给大脑 |
| `brain.py` | LLM 工具调用循环 | 模型**不能直接发游戏指令**（结构上排除注入）；同技能同参数连续 3 次 → 判定打转并提示 |
| `memory.py` | 目标栈 / 事实本 / 行动流水 | 上下文会被压缩 ✗ → 长时记忆必须落盘 ✓ |
| `prompts/system.md` | 给模型的身体说明书 | 把**所有已知身体限制**写进去（没有 GUI、潜行不防坠、`hotbar` 从 1 开始、自述不算证据…） |
| `run.py` | 入口 + `doctor` 体检 | 体检会查 schema 新鲜度、部署字节数、心跳年龄、假人在线、API 配置 |

py agent/run.py journal -n=30

## 4. 接入你自己的 API

只需要一个** OpenAI 兼容**的 `chat/completions` + tool calling：

```powershell
$env:AGENT_API_BASE = "https://api.openai.com/v1"   # 或任何兼容端点（本地 vLLM / 中转 / 自建）
$env:AGENT_API_KEY  = "sk-..."
$env:AGENT_MODEL    = "gpt-4o-mini"                 # 换成你要用的模型

py agent/run.py plan "砍一棵树，把原木丢到箱子旁边"   # 只出计划、不执行（安全预览）
py agent/run.py ask  "砍一棵树并回到房子门口" --steps=12
```

- `plan` = **dry-run**：模型照样思考、照样选技能，但**不执行** ✓ 第一次接新模型先用它 ✓。
- 模型**必须支持 tool calling**（function calling）✗ 不支持的话它只会说话、不会动手 ✓。
- `AGENT_API_BASE` 指向的地址要能**响应 `/chat/completions`** ✓
- 沙箱可能禁外网 ✓：连不上时报错会直接说明是网络还是 HTTP 状态码 ✓ 不会静默失败 ✓。

## 5. 安全设计（不是可选项）

| 机制 | 作用 |
|---|---|
| 模型只能说技能名 | 模型**无法**直接发游戏指令 → 命令注入从结构上被排除 |
| 技能自带验收 | 动作自述不算结果 ✓ 必须 `verify`/`scan` 复核 ✓（`place_at` 曾报告 `false` 而方块其实落在邻格） |
| 脚手架默认禁用 | `give_item` 在代码层被拦住 ✓ 用户要求"假人必须自己从零获取材料" ✓ |
| 打转检测 | 同技能同参数连续 3 次 → 提示换思路并记日志 ✓ 防止无限烧 token |
| 步数预算 | `--steps=N` 上限 ✓ 不会失控 |
| 反射独立于模型 | 还击/吃饭走本地确定性逻辑 ✓ 不依赖 API 延迟 |
| 全量记账 | 每次技能调用写 `agent/memory/actions.jsonl` + `.md` ✓ 复盘有第一现场 |

## 6. 已知边界（诚实清单，别当成 bug）

1. **合成必须借海龟** ✗：`/player` 没有 `craft` ✓ 假人也没有合成界面 ✓
   → 需要在 cc0 上补一个「转发合成请求给海龟」的动作（`broadcast_cmd` 已存在 ✓ 但海龟端的程序还没接上 ✓）。
2. **熔炼走漏斗** ✓：假人点不开熔炉 ✗ 但漏斗可以 ✓ 丢料上漏斗 → 炉子 → 下方漏斗掉出 → 自动拾取 ✓ 全程零界面 ✓。
3. **通道是共享的单车道** ✗：一台计算机一次只吃一条指令 ✓ 长任务（筛矿 12s、砍树 60s）会把通道占住 ✓
   → 表现是"下一条指令要排队" ✓ 超时信息里会打印**队列深度**帮你区分"没被取走"和"正忙" ✓。
4. **`say` 依赖 Chat Box 外设** ✗：只有 cc0 有 ✓ → 技能层会先 cmd0 再 cc0 最后 tellraw 兜底 ✓。
5. **GPS 基站**：`locate` 已经能返回坐标 ✓ 但完整 4 基站网络还在搭 ✓。
6. **服务端本地化**：任何"在回传文本里找英文关键词"的写法都会失效 ✗ 见 `docs/错题本.md` F2 ✓。

## 7. 加一个新技能（三步）

1. 在 `skills.py` 的 `SPEC` 里声明：名字、说明、参数（名字→(类型, 说明, 是否必填, 默认值)）、以及治理标记（`danger` / `long` / `scaffold`）。
2. 实现 `s_<名字>(self, ...)`，**必须返回 `self._r(ok, evidence)`**，并且：
   - 参数名要按 `agent/action_schema.json` 里的真实名字来 ✓（别猜 ✓）
   - 完成后用世界状态复核 ✓ 不要拿动作自述当结论 ✓
3. 跑 `py agent/run.py tools` 确认它出现在表里 ✓ 再用 `do <名字> k=v` 手动验一次 ✓。

> schema 过期会被 `doctor` 拦住 ✓：改了 `cc-tweaked/agent_bridge.lua` 之后要重跑
> `py tools/gen_action_schema.py` ✓（它按 sha1 校验 ✓）。

## 9. 界面问题：两条腿走路（2026-09-13 定案）

**问题**（用户提出）：科技包里很多机器**自带 UI**（AE2 终端、机器配置界面…）✗
而 Carpet 假人**开不了任何界面** ✗（没有客户端 ✓）→ 那这套东西还怎么推广？✗

**结论：这不是缺陷，是分岔点 ✓ 两条腿都要有 ✓。**

### A 线：绕开界面（首选，也是科技包的正确玩法）

机器本来就是为"机器之间自动化"设计的 ✓ 界面只是给人看的 ✓ 所以：

| 需求 | 免界面路径 |
|---|---|
| 物品进出 | 漏斗/管道/物流 ✓ 假人只需要"丢/放" ✓ **已验证** ✓ |
| **按需合成** | **AE2 的 ME Bridge**（Advanced Peripherals 外设 ✓）直接 `craftItem(...)` ✓✓ 零界面 ✓ |
| 机器配置 | 右键扳手 ✓ / 机器自带的上位接口 ✓ / AP 的各类 Bridge ✓ |
| 物质转化 | 整合包里有 **Project E** ✓（已在游戏画面里确认 EMC 32 ✓）→ 能量凝聚器可被漏斗喂料 ✓ 也属免界面路径 ✓ |

**判断准则（可推广的那句话）**：面对任何一台机器，先问
**"它有没有非界面的控制路径？"** ✓ —— 成熟科技包里答案通常是**有** ✓
因为自动化与物流本来就是它的卖点 ✓ 我们不是在对抗整合包 ✓ 是在用它的自动化层 ✓。

### B 线：我来操作界面（兜底，通用，已实测可行 ✓）

```
tools/grab_window.ps1 (PrintWindow+PW_RENDERFULLCONTENT) → 我 read_image 看图
   → 说出像素坐标与理由 → agent/screen.py 换算成屏幕坐标 → SendInput 点击
```

- **已实测成功** ✓：抓到 1600×900 真实画面 ✓ 并读出"玩家背包开着 ✓ JEI 在右侧 ✓
  `1/324` 页 ✓ 指着深色橡木原木 ✓ `EMC: 32` ✓" —— 说明**看图识别可用** ✓。
- 关键工程细节（都踩过坑 ✓）：
  - 普通 BitBlt **抓不到**用独立翻转/硬件覆盖层的游戏画面 ✗ → 只会拍到桌面 ✓
    必须 `PrintWindow(..., PW_RENDERFULLCONTENT=2)` ✓ 并**检查平均亮度** ✓（全黑=失败 ✓）
  - 窗口可能停在 `(-32000,-32000)` 且尺寸退化成 `160x28` ✗ → 那是"保存位置跑到屏幕外" ✓
    必须先 `-Fix` 救回来 ✓ 否则抓到的是垃圾 ✓（`screen.py healthy()` 会直接拦下 ✓）
  - 点击是**屏幕绝对坐标** ✓ 必须用**当前**窗口矩形换算 ✓ 窗口一动旧坐标就作废 ✓
  - 本机**没有 `pwsh`** ✗ 只有 `powershell.exe` ✓（`powershell_exe()` 按顺序探测 ✓）
- **安全默认**：`click()` 默认 `dry_run=True` ✓ **只看不点** ✓
  在别人的游戏里点击是有副作用的动作 ✓ 点错一下可能丢物品/误触 ✓
  要真点必须显式 `live=True` ✓ 且每次点击都写进行动日志 ✓。

### 附赠收益：一个**独立于 CC 的验证通道** ✓

以前"世界状态才算证据"只能靠 CC 的 `survey`/`block_state` ✓；
现在还能**亲眼看** ✓ —— 平台有没有悬空 ✓ 假人站在哪 ✓ 门有没有被堵 ✓
都能用眼睛直接确认 ✓ 这对"用户看得见、报告看不见"的那类问题（错题本 E6 ✓）尤其值钱 ✓。

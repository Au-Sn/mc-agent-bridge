## 3. 输出 schema（★一条物种一行✗★）

```json
{
  "schema": "dshbridge/registry_blocks@1",
  "exported_at": "2026-10-03T23:59:59",
  "mod_version": "2.18.2",
  "game_version": "1.20.1",
  "count": 24081,
  "blocks": {
    "minecraft:oak_leaves": {
      "collision": "canopy",
      "max_height": 1.0,
      "has_block_entity": false,
      "destroy_time": 0.2,
      "tool": "hoe",
      "requires_correct_tool": false

```

★三处**刻意**的决定✗★：
1. ★`collision` 用**现有家族名的闭集**✗★：★`full` ／ `slab` ／ `fence` ／ `machine` ／
   `canopy` ／ `pass` ／ `air` ／ `liquid` ／ `other`✗★ —— ★就是 `mapread.shape()` 今天返回的那几个 ✓
   ⇒ ★这样"★`is_floor`／`blocks_space` **签名与语义都不动**★"那条要求**自动满足**✗★ ✓
   （★任务书里那套 `fence_15`／`snow_layer` 更细 ✗ 但**细的用 `max_height` 表达**就够了 ✓
     要细名可以把 `collision` 拆成两个字段 ✗ 那是选项之一，见 §6✓★）
2. ★`max_height` 是**数值真值**✗★：★它是"★能不能站★"那条判定的**硬来源** ✗ 也是阶段 3 一致率
   判据要的**形状敏感量**✗★ ✓（★今天那个 `solid=` 之所以不区分形状家族 ✗ 就是因为没有它 ✓）
3. ★★`tags` **不在这里**✗★★：★标签是**数据侧**的（★datapack JSON ✗ 已实测覆盖 93%✓★）✗
   ★由 `tools/tag_census.py` 离线读 ✗ 一次扫描 311 个 jar 就够 ✗ 不需要动模组✗★ ✓
   ⇒ ★两个来源**分开** ✗ 物理的走这里 ✗ 语义的走数据侧✗★ —— ★这正是三铁律要的形状✓★ ✓

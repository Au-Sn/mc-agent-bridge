## 二、寻路：**规划 → 分跳 → 验真值 → 重规划** ✓ 现状

### 2.1 两道寻路（谁在算）

| 层 | 谁 | 干什么 | 强弱 |
| --- | --- | --- | --- |
| **中间层**（Python） | `pathplan.Planner`（A\* ✓） | 全局规划 ✓ 拆成 ≤6 格的腿 ✓ 判定连通区/内陆 ✓ 目标站不住就挪 ✓ | 缺点：图是**快照** ✓ 未知格一律当"不能走" ✓ |
| **模组**（Java） | `astarPath` ✓ | 单条指令内的局部寻路（`dshwalk` ✓） | 优点：**逐 tick 真实推进** ✓ 贴着世界走 ✓ |

分工 ✓：**中间层决定"往哪走、走几步停一下"** ✗ 模组负责**这一小段真的走过去** ✓
（实测：一跳 ≤8 格最稳 ✓ 超过就回到"单发长走"掉虚空的坑 ✗ ⇒ `SAFE_WALK=8`／`chunk≤8` ✓）

### 2.2 一条指令的完整旅程 ✓

```
walk_route(目标)
 ├─ 读假人真实坐标（dshdigest ✓ 浮点脚高 ✓⇒LEVEL = round(脚高) ✓ P101）
 ├─ 建/取图 → **求证**（外接框 ✓）→ 规划（A* ✓）→ **按路补验 → 重规划** ✓
 ├─ 每一跳：发 dshwalk（≤8 格 ✓）→ 等回执 → **独立读位置验真值** ✓
 │    └─ 没到？→ 换"短补腿"（≤3 格 ✓）→ 还不行？→ **从实测位置重规划** ✓（上限 2 次）
 ├─ 探路（`sweep` ✓ 默认 4 格）：实地找**道中障碍** ✓ 探到就记进 `BLOCKED` ✓ 之后规划**绕开** ✓
 └─ 收尾：**判"人在不在目标那一格里"** ✓（不是判到角点的距离 ✗ 第 18 轮修的假"没到"✗）
```

### 2.3 四道防掉虚空的闸 ✓（都是踩出来的）

1. `walk_to` **距离闸**：>10 格 ⇒ 拒发 ✓（单发长走实测掉过两次虚空 ✗）
2. `walk_to` **站不住闸**：目标格站不住 ⇒ 拒发 ✓ **但先独立读一次复核** ✓（不拿过时图拒人 ✓）
3. `walk_route` **连通区闸**：目标不在**你脚下这块连通平台**里 ⇒ 拒 ✓（中间隔着虚空 ✓）
4. **内陆闸**：目标在平台边上 ⇒ 自动挪到内陆格 ✓（防踩空 ✓）

### 2.4 现在还差什么 ✓（诚实说 ✗）

- **`walk_to` 是模组自己的到达判定** ✗ ⇒ 它还按"角点距离"判 ✓（`int()` 那类偏差没在模组侧修 ✓
  要改得动 Java ＋ 重启 ⇒ **后置** ✓ 中间层已用"在不在那一格"兜住 ✓）
- **Z 字绕路的代价**：一跳 2.7~8.3 秒 ✓ 中位约 7.6 秒 ✓（比"单发长走"稳得多 ✓ 但慢 ✓ 认了 ✓）
- **障碍记忆会过期**（24 小时 ✓）⇒ 过期后要重探 ✓（宁可重探 ✓ 不留永久错误封锁 ✓）

### 3.1 关联关系（一句话一条 ✓）

- **①网关 ↔ 模组**：网关把"一条指令"塞给 CC 电脑 ✓ 回来的行数由模组返回值决定 ✓（多回行 = 不加往返 ✓ v2.16 就是这么加的 ✓）
- **②中间层 ↔ ①网关**：所有读世界都走 `channel.py` ✓ ⇒ **节流与收手逻辑只有一处** ✓
- **②中间层 ↔ ③大脑**：MCP 工具 ✓ ⇒ 大脑**只看得见工具** ✗ 看不见指令细节 ✓（好 ✓：换协议不用改大脑 ✓）
- **③大脑 ↔ ④工程**：错题本/交接文档是**给下一个我**的记忆 ✓（每次重启会话都会读 ✓）
- **②中间层 ↔ ⑤镜像**：只有**重建模组**才用得到 ✓（运行时无关 ✓）

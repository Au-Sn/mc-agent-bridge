⇒ 结论 ✓：客户端画这个实体时**不走**那套默认皮肤贴图 ✗ ⇒ 唯一可靠的路是
**在服务端把皮肤写进玩家档案的 `textures` 属性** ✓（客户端只认那里的 **URL** ✓）。

## 3. 落地设计

### 3.1 皮肤从哪来（★优先级从高到低★ ✓）

| 顺序 | 位置 | 用途 |
|---|---|---|
| ① | `config/dshbridge/skins/*.png` | **你自己加的** ✓ 覆盖内置同名 ✓（G1 ✓ 不用重编译 ✓） |
| ② | jar 内 `assets/dshbridge/skins/*.png` | **随包发布**的 ✓（现在有 `deepseek` / `catgirl` / `yuyu` ✓） |

元数据 ✓：两边都可以放 `skins.json` ✓（`file` / `name` / `model` / `note` ✓）；
**没有 json 也能被发现** ✓（默认 `name=文件名` ✓ `model=wide` ✓）⇒ 丢图即用 ✓
外部目录的 `skins.json` 与内置**合并** ✓（同 `name` 时外部赢 ✓）

### 3.2 怎么送到客户端（★这是关键✗★）

客户端只认 **URL** ✗ ⇒ 模组自己起一个**只绑回环**的小 HTTP 服务 ✓：

```
GET http://127.0.0.1:<自动端口>/skin/<name>.png?v=<皮肤指纹>
```
- **只绑回环** ✓（不对外开端口 ✓ 不干扰 310 个模组的整合包 ✓）
- **`?v=` 用皮肤内容的 sha1 前 8 位** ✗✓ ⇒ **换图即换 URL** ✓ ⇒ **不会被客户端缓存骗** ✓
  （"换了皮肤没反应"最常见的坑就是这个 ✓）
- 端口 0 ＝ 让系统给空位 ✓ 启动时打印实际端口 ✓（G4 ✓）

### 3.3 怎么让客户端立刻刷新

给 `ServerPlayer.getGameProfile()` 注入属性 ✓：
```json
{"textures":{"SKIN":{"url":"<上面的URL>","metadata":{"model":"wide|slim"}}}}
```
base64 后放进 `prof.getProperties().put("textures", new Property("textures", b64, null))` ✓
然后**重发一次 player-info**（`ClientboundPlayerInfoUpdatePacket` 的 `UPDATE_GAME_PROFILE` ✓）
⇒ 客户端立刻去取新图 ✓（不用重连 ✓）

### 3.4 指令面（想清楚再写 ✓）

```
/dskskin                     列出所有可用皮肤（名字/模型/来源/尺寸校验结果 ✓）
/dskskin <名字> [玩家]        给某个玩家（默认假人 Bot）换上 ✓
/dskskin off [玩家]          清掉注入 ⇒ 回该玩家原本的皮肤 ✓
/dskskin base <url>          覆盖 URL 前缀（多人服/公网用 ✓ 默认 127.0.0.1 ✓）
/dskskin reload              重扫两个目录（加图后不用重启游戏 ✓）
```
回执**全 ASCII** ✓（项目纪律 ✓ CC 通道不吃非 ASCII ✓）

### 6.2 路上踩到的四个真 bug（都留了证据 ✓）

1. **`UPDATE_GAME_PROFILE` 是 1.20.2 才有的** ✗ ⇒ 编译期"找不到符号"×2 ✓
   ⇒ 改用 1.20.1 就有的 **`PlayerInfoRemove` ＋ `createPlayerInitializing`** ✓
2. **IPv6/IPv4 张冠李戴** ✗：`InetAddress.getLoopbackAddress()` 返回 **`::1`** ✓
   而 URL 写的是 **IPv4 字面量** ✗ ⇒ **判据 A7「真去连一下」当场抓到** ✓
   （只看回执里那个端口号的话 ✓ **永远发现不了** ✗）
3. **缓存指纹用错了维度** ✗：`?v=<内容 sha1>` ⇒ 内容不变 ⇒ **URL 不变** ⇒ 缓存永远命中 ✓
4. **只更新 PlayerInfo 不够** ✗：实体已在世界里时 ✓ 客户端照旧用老数据画 ⇒ 外观不变 ✓

## 7. 复发记录（2026-09-26 ✓ ★就是 §6 那件事又来了★ ✗）

**用户报** ✓：「皮肤又掉了，怎么回事」

**查出来的真因（两条 ✓ 都指向同一处）** ✗：
1. **两套系统在抢同一个 `textures` 属性** ✗ ——
   · `BotSkin`（`/dshtskin` ✓ 单独的类 ✓ 走 `dsh_bot_skin.txt` 里的 URL ✓ 我这边是 `:8791` ✓）
   · 模组自己的皮肤子系统（`/dskskin` ✓ 自己起回环 HTTP ✓ 端口自动选 ⇒ **这次是 `:54625`** ✓）
2. **`BotSkin` 那条路本质上走不通** ✗：它注入的是**未签名**属性 ⇒ 客户端的会话服务直接拒 ✓
   游戏日志实锤 ✓：`Signature is missing from Property textures` ✗（反复出现 ✓）
   ⇒ 这也解释了「为什么服务端说注入成功、客户端却毫无反应」✗

**修法（照 §6.1 记录的已验证路走 ✓）**：
```
/dshtskin clear          # 把抢属性的那套清掉 ✓
/dskskin off             # 模组自己那套也先清 ✓
/dskskin deepseek        # ⇒ set=deepseek player=Bot url=http://127.0.0.1:54625/skin/deepseek.png ✓
```
再把 `<游戏目录>\dsh_bot_skin.txt` **删掉** ✓（留 `.disabled` 档 ✓）
—— 不然假人**下次登录**它又会注入回来 ✗（§6.2 那四个 bug 的同类 ✓）

**判官纠正** ✗（我以前记错了 ✓）：客户端取没取图，
  · **不是** `logs/skin_http.log` ✗ —— **那个文件根本不存在** ✗（我拿它当判官查了半天 ✗）
  · 我那个 `:8791` 小服务的访问打在 **`logs/skin_server.log`** ✓（stdout ✓）

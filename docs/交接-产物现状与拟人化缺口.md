# 交接报告：产物现状与拟人化缺口

> 日期：2026-11-02 ｜ 交接对象：接手"让假人更像人"这一段的人（或下一个我）
> 这份报告解决一个问题：**别把"它能干活"当成"它像个人"。**
> 现在这个产物是「能干活、不会死、可验证」，但离「像人」还有大约一半的路。

---

## 一、先明确产物是什么

这个项目的交付物不是"假人会通关"，而是**一个能换脑的「在场层」**：
任何 agent 接上来，它都像一个玩家一样在场——能看、能走、能动世界、能听会说、
有自己的性格与记忆、出事不死、离开不散。

**"像人"不是修辞，它有可判定的反例表**（规格 §1 的 N1~N10）：
瞬移、悬空、抽搐、一帧完成、无故破坏、全知、无缘由、无情、无记忆、不复盘。
十条里**每条都能写成机器判据**，这是这个项目最硬的设计。

## 三、具体"不够像人"的清单（按用户能感知的顺序）

### 1. 闲下来会抽搐
现象：不动的时候朝向在两个角度之间每 tick 跳，肉眼就是"抽搐"。
根因（已查实）：**同一个 tick 有两个写者**——我们的转身逻辑写目标角，另有一个"外部"写者每 tick 把它改成另一个固定角（相差约 104°）。谁后写谁说了算，于是闪。
现状：`HOLD_YAW` 在 tick 最末尾重申朝向，把外部写从 **40 次压到 7 次**，但没归零。
没做完的：剩下 7 次发生在我们 `ServerTickEvent.END` 之后，需要在更低优先级或更晚的钩子上按，或者找出那个写者是谁。
**这一条是 M6 的 E 模块的前置**——不解决它，待机习惯做不了（任何待机动作都会被这个写者毁掉）。

### 2. 没事做的时候不会自己找事
人的空闲是有内容的：看看四周、整理背包、走到窗边。现在 `AUTO_IDLE` **默认关闭**，
原因写在代码注释里："它会旋转准星"——也就是会加重上一条。
所以现在它闲下来就是站着，这不像人，像待机程序。

### 3. 说话是语码不是对话
`say.py` 是 17 个 ASCII 语码（ok/start/done/no_path/…），未知码降级成 `unknown`。
这是为了"说人话不可靠时至少说明状态"，方向对，但它**不是对话**。
真正的对话层（ACP）依赖外部 harness（`tools/dsh_acp.py` 是个 ACP 客户端），
而这条链路**没有判据守**，且占了 13 个工具（3.6%）。

### 4. 记不住"发生过什么"
`memory.py` 只记**地标**（家、箱子、床、上次位置……），带选择性保留。
但"今天挖了一百个铁、被苦力怕炸了一次、把箱子整理过"这类**事件记忆完全没有**（H 模块零文件）。
所以它不会复盘，也不会从经历里改行为。

### 5. 不会自己拆任务
`exec_task` 只能按给定的一串坐标依次走，**没有优先级、没有中断、没有依赖**。
`orchestrator` 能把一句话落成一条 job 并保证"一条任务只发两条消息"，但 job 排队之后就没人管了。

### 6. 缺两个角色
L5 设计官（自己设计产线布局）和 L7 汇报官（把做过的事讲清楚）都**完全没有**。
所以现在的"多智能体"是：判别 + 执行 + 校验三个角色有骨架，设计和汇报是空的。

### 7. 行为库 9 条只实现了 4 条
未实现的是 `enter_house` / `leave_house` / `chop_tree` / `store_to_chest` / `handle_night`。
注意它们**如实报 `not_implemented`**（这是我们刻意守的诚实），但诚实地"不会"仍然是"不会"。

### 8. 蓝图会照着搭，不会"设计"
检索（包里 260 个结构文件可搜可读）、移植（对着现场算账、逐格搭建、幂等、悬空不硬放）都通了。
但"没有现成图时自己设计"只做到**配方图算料**（20764 个产物 → 元件清单），
**布局怎么排**还是手工定的。

## 四、为什么会停在这

不是能力不够，是顺序问题：

1. **先做"能力"再做人味**是对的——人味最依赖"身体不出事"。
   但 D3（身体不出事）还没真正跑满（只跑过几档、远不到 3 小时 × 2000 次调用），
   所以人味这部分一直"不敢开"：待机动作会加剧抽搐，自由移动会加剧摔落风险。
2. **判据先行的纪律**让每个模块都必须有"能先自检变红"的判据，
   这拖慢了铺开速度，但换来的是：现在 118 项判据全绿，而这不是装饰。
3. **今天的两处修补**（`dshdig` / `dshplace` 都没挥手、工具选择早就有且是对的）
   说明**"人感"这类东西最容易漏检**——判据只验"世界变没变"，不验"手上有没有动作"。

## 六、判据纪律（这几条不能破）

1. **判据先自检能红**——证明不了会失败的判据等于没有。
2. **没数据就说没数据**——`turn_profile` 在轨迹脏时输出 `reason=trace_noisy`，这是正确行为，不要为了"全绿"去改它。
3. **只认世界真值**——校验只看方块/背包 NBT，不信执行者自述。
4. **新判据必须进闸门**——"写好了没进闸门就等于它不存在"（覆盖门会在 CI 里抓）。
5. **把事故做成回归测试**——`bulk_guard_test` 的 G1 就是"填掉 CC 计算机"那次事故的回放。
6. **不许用"它会做什么"量完成度**——用 D1~D7，否则最贵的那条（身体不出事）会被挤掉。

## 七、已知的坑（血泪清单，按代价排序）

| 坑 | 真相 |
|---|---|
| 一次 `fill` 填掉了 CC 桥接计算机 | 整套系统当场断线。现在 `bulk_guard` 三条硬拦（没扫过/命中禁区/有方块实体全拒绝） |
| `thermal:dynamo_stirling` 的 `fe=none` | 它在烧煤、看着在发电，但**不对外输出 Forge 能量**，机器永远充不上。查 `dshcaps` |
| Forge 能量不会在相邻方块间自动流 | 必须有会主动拉的管子；而**每个模组的管子只连自家网络** |
| `dshplace` 的 item 参数不能带冒号 | `StringArgumentType.string()` 只吃单字，带 `:` 解析失败，必须短名或加引号 |

| 平台必须与地面同层 | 建在 y=71（地面 y=70 之上）时四周悬空，`no such support face` |
| 假人掉进虚空会死 | 拉假人要用 `/raw player Bot spawn at <x> <y> <z>` 指定安全点 |
| `AUTO_IDLE` 默认关闭 | 因为它会抢朝向，加重抽搐。想让空闲有内容，先解决 yaw 写者 |

> 但它还**不会闲、不会记、不会自己安排事**——这三件事就是接下来要做的全部。
